## 一句话定位（开场先说）

> "我们把整个 MDC 通知系统 —— **460 个仓库** —— 变成了一个能问的东西。
> 它回答三类以前要问遍全组的问题：**出事了影响谁、为什么挂、改这里会连累谁**。
> 每条结论都带出处：源码到行号，配置到表和快照。
> **而且它会明确告诉你什么它答不了** —— 这一条比前面三条更重要。"

## 第 1 幕 · 出事了，影响谁（零生产访问）⏱ 90 秒

**点卡片**：`告警影响面`

**说**："这是运维接到告警的第一分钟。注意 —— **它一个生产系统都没碰**，
纯粹靠我们的代码图和业务图推出来的。"

**看点**：
- 从告警文本里**认出仓库**（真实数据 **466/500 = 93.2%**，抽查 0 认错）
- 它产/消的 **topic** → 路由到的**业务用例** → **渠道** → **该通知谁**
- 每一条带快照出处

**这一幕的杀手锏是它说"不知道"的地方**：

> "看这里 —— 业务用例它没有直接报一个数字，而是说'**精确连接算不出来，因为没有同环境的路由表**'，
> 然后给一个**上界**：'最多 N 个'。
> 一个只会报数字的系统这里会给你一个 0，而 0 会被读成'没有业务影响' —— 那是事故里最贵的一句错话。"

## 第 2 幕 · 为什么挂（读生产日志）⏱ 2 分钟 —— **高潮**

### A 方案：`MCP` 灯是数字（日志链路已开）

**点卡片**：`生产日志根因` —— **和第 1 幕是同一条告警**。这就是演示本身：一条告警的两半。

**说**："同一条告警，现在问'为什么'。它会派一个**独立的调查员**去读生产日志。"

**看点（边跑边指）**：
- 面板**逐步流式**显示：查哪个应用、哪个 source、哪个关键词、命中多少行
- 每一步带 **`logdream · log.read` 徽标 + 耗时**
- 有拒绝的显示 `✖`，并且**区分"本地拒绝（没发请求）"和"服务器没响应"**

**这一幕要讲的三句话**：

1. **"关键词不是搜 ERROR。"** 它搜的是**那个仓库真实会抛的异常类**、它产/消的 topic、它服务的渠道 ——
   全部从我们的代码图和业务图推出来。**通用 AIOps 推不出这一部分**，这是我们的位置。
2. **"日志不进模型，也不进聊天记录。"** 原始日志只在调查员进程内存里，
   经三层防护（取数时脱敏 → 出口再扫一遍并记账 → 硬性条数/长度上限）才变成结构化证据包。
   落盘的会话记录里**不可能**出现原始日志 —— 这条有专门的测试：往日志里种手机号，断言返回包任何地方都找不到。
3. **"没查到 ≠ 没问题。"** 面板把"**查了没有**"和"**没查**"分开列。
   比如应用名核不上就明确拒绝并说明原因 —— 拿猜的应用名去查会返回空，而空会被读成"没问题"。

### B 方案：`MCP` 灯是 `MCP off`（日志链路未开）

**照样点那张卡**，它会明确说"日志查询开关未开，没有读任何生产数据"。

**这时候这样讲 —— 这是加分项，不是减分项**：

> "日志链路已经建好了，三台 MCP 都真机验证过。现在没开，是因为**内网复现了三个解析缺陷，
> 我们修完了、补了回归测试，正等内网跑完验收才开** ——
> 这个项目的规矩是：**能给出确定错误答案的功能，宁可先关着。**"

然后指回第 1 幕的结果："**影响面这一半不需要生产访问，今天就在用。**"

## 第 4 幕 · 一条通知从头到尾走了哪些地方 ⏱ 90 秒

**点卡片**：`全链路到出口`

**说**："这是业务侧最常问的一条 —— 一个用例发出去到底经过什么，客户最终怎么收到。"

**看点**：用例 → 渠道规则 → **权威路由表**（厂商 / SLA / delivery_path）→ topic →
投递任务 → 出站 API → **厂商** → SMSC / APNs / ProofPoint / 打印出口。

**这一幕同样靠"说不知道"加分**：

> "看厂商这一栏。权威路由表里写的是 `HTCL`，它就**原文照抄 `HTCL`**，
> 并标注'canonical 映射未经业主签认'。它**没有**替我们说'走 3HK'。
> 权威表只覆盖 push 和 SMS，其余渠道它给的是**渠道级上界**：'最多这几家'。
> **业主一句确认，这里就能升级 —— 但在那之前它不替业主做决定。**"

顺带一句可讲的硬事实：`delivery_path 3 = HASE Real Time Standard (MDC)`，
而且它明确说这是**分类，不是路由开关** —— 这个码表是从代码里三处一致地找出来的。

## 第 5 幕 · 最不能出问题的是哪些服务 ⏱ 60 秒

**点小按钮**：`核心仓库 Top 10`

**说**："这一幕讲的是方法，不是榜单。"

> "按 Maven 依赖数排，`api-common` 一定第一 —— 所有人都依赖它，但它不承载任何消息。
> 而一个投递任务承载了全行所有短信，却没有任何仓库依赖它。

**并且它每次都会列出算不了的三个维度**（生产流量 / 故障历史 / 测试覆盖），
**并写清各自卡在谁那里** —— 这一句直接连到收尾的资源申请。

## 应答备忘

| 会被问什么 | 怎么答 |
| --- | --- |
| **"数据准不准？"** | 每条结论带 `仓库/文件:行号` 或表/快照出处，当场展开核对。存疑一律标"待核实"，供应商级不夸大成渠道级。 |
| **"它会不会瞎编？"** | 三处可现场验证：① 引用校验绿灯；② 事故调查员每一步查了什么都在面板上；③ 内测期可以点"查看原文"核对调查员没编造。 |
| **"生产数据安全吗？"** | 只读、不写任何仓库；原始日志只在调查员进程内存，三层脱敏后才出来；落盘的会话记录里不可能有原始日志，有专门的种 PII 测试。 |
| **"和 Copilot / 通用 AIOps 有什么区别？"** | 通用工具没有我们的**代码图 + 业务路由图**。第 2 幕那些关键词、第 4 幕那条到出口的链路，是这两张图推出来的 —— 换个大模型这部分不会自己出现。 |
| **"下一步？"** | 三份数据（见收尾）+ 契约索引（案例 4 收尾，1–2 天，不等任何人）。 |
