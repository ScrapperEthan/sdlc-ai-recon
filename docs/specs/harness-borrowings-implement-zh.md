## 阶段 A —— 预算台账

### A.0 先跑一行（这就是那个悬着的 Q3）

`_bounded_payload()`（agent 侧）截断工具结果时，**留不留"给了多少 / 一共多少"这个标记**？

Ask 侧的 `context_budget.shrink_tool_result()` 是留的：
逐路径记 `{"path":..., "kind":"list", "kept": N, "total": M}`，
压不下去时还会返回一个 `_truncated: true` ＋ "这是预览不是全部，别据此下结论" 的信封。

- **留了** → A.1 直接读它。
- **没留** → **在这一阶段一起加上**，因为台账本来就要这个数字。
  这不是额外工作，是同一件事的两半。

🔴 **如果两个模式在这件事上不一致（Ask 告诉模型"你只看到了 90/361"，agent 不告诉），
那本身就是一个缺陷**，比台账更值得先修 —— 请在回报里单独指出来。

### A.1 要记什么

**每轮**一条记录，进已有的 turn / checkpoint 记录里（放哪由你们定）。
**只记数字和名字，不记内容**：

| 字段 | 说明 |
| --- | --- |
| 各 lane 的分配与实际占用 | `Budget.report()` 已有的东西，原样落 |
| 本轮 dropped 的历史轮数 | 一个整数（现在这个数**从来没被写下来过**，这是整件事的重点） |
| 有没有触发结构化截断 | 布尔 ＋ 触发次数 |
| 有没有触发"整块压不下去"的预览信封 | 布尔 |
| 触发截断的工具 | **工具名**，可以是真名 |
| agent 侧的对应用量 | 模型调用次数、replan 次数、tool_cache 命中次数 |

### A.2 契约（不可违反）

1. **不记任何工具结果内容、不记任何参数值。** 台账是用来统计的，不是用来复现的。
   工具名可以，参数不行 —— 参数里会有仓库名、告警文本、tracking id。
2. **不改 `Budget` 的行为。** 这一阶段只读它的报告，一个字节的预算逻辑都不动。
3. **写失败不许影响回答。** 台账写盘失败 = 记一条 warning，答案照常返回。
   这跟上游 spill 的"尽力而为"是同一条规矩：辅助设施的故障绝不能把一次成功的调用变成失败。
4. **落盘用现有的原子写路径**（`webapp/atomic_json.py`），不新造一套。

### A.3 验收

- 跑一个多轮会话（`LLM_MOCK=1` 即可），台账里能读出 dropped 计数和截断计数。
- 一条断言：**台账记录里不出现任何工具参数值**（用一个含可识别字符串的假参数跑一遍，
  断言那个字符串不在落盘文件里）。
- 一条断言：**台账写盘抛异常时，`answer()` 仍返回正常结果。**

### A.4 不做什么

- 不做任何 UI 展示（先攒数据，展示以后再说）。
- 不做聚合/报表脚本。
- 不因为台账新增任何配置开关（复用现有持久化开关）。

## 阶段 B —— `ask_user_question`

### B.1 它防的是什么

**不知道的时候，模型编一个，而不是停下来问。**
我们被内网抓过的错，一多半是这个形状：示例 JSON 里编了值、
给字段安了含义（`55` 说成"存不下引用"实为"扫过且干净"）、`hkl` 读成 `hk1`。
而这些**恰好都是业主一句话能定的**（`send_mode=0` 至今 903 行 pending、244 行、alias 表）。

内网这一轮的实测（真 provider，两个合成的未知语义用例）是 **0/2**：
既没承认未知、也没索取证据、也没做显式假设。
**所以"prompt 里写了一句先给假设再澄清"不能算数，得给模型一条合法的出路。**

### B.2 形态：`pause` → 下一个 HTTP turn `resume`

内网已确认：当前 SSE **不能**在一个 turn 里挂起等浏览器输入；
但 `done` 带结构化 `pending_question`、下一轮用 `resume_from_run_id / session` 绑回答，
**能做，且贴合现有的 checkpoint ＋ pause/resume 架构**。

大致要动的面（**位置由你们定**）：

| 面 | 要什么 |
| --- | --- |
| 工具注册 | 第 18 个模型可见工具的 schema ＋ 一个 dispatch 分支 |
| Ask 循环 / agent 循环 | 收到该调用 → 不再迭代，走"带问题结束" |
| `done` 事件 | 增加 `pending_question` |
| checkpoint / session | pause reason = 等人回答 |
| 前端 | 渲染选项卡片；回答作为下一轮输入，**带上绑定 id** |

### B.3 问题与答案的形状（照抄上游，这部分别自由发挥）

**问题**：一次可以问多个；每个带**稳定 id**、问题文本、可选短标题、
可选选项列表（`label` ＋ `description`）、多选开关。
**推荐项放第一个，label 末尾加 `(Recommended)`。**

**答案**：`{"answers":[{"id": "...", "selected": ["<label>"], "custom": "<自由文本>"}]}`
—— `custom` 在**多选**时是**补充**，在**单选**时是**覆盖**。id 原样回传。

### B.4 契约（不可违反）

1. 🔴 **这个工具不读任何东西。** 没有数据源、没有文件、没有 DB、没有 MCP、
   不新增任何读权限。**业主放行它的全部理由就是这一条** —— 它一旦长出读能力，
   放行的前提就没了，要重新走确认。
2. 🔴 **pause 理由必须显式，绝不许伪装成 `completed`。**（内网明确提的）
   一个"在等人"的 run 和一个"做完了"的 run 在记录里必须能一眼区分。
3. 🔴 **答案绑定必须是显式的。** 下一轮用户如果发的是**别的问题**而不是回答，
   **必须当成新一轮**，不能被误读成对上一个问题的回答。
   没带绑定 id 的输入一律走正常路径。
4. **owner 隔离照现有规矩**：问题只对发起的那个 browser 可见，
   复用 session / checkpoint 已有的 fail-closed 隔离，不新开路。
5. **超时要有归宿。** checkpoint TTL 是 24 小时；
   一个到期都没人回答的 pending question，必须**明确过期**，
   不能留下一个既不能 resume 也不算结束的状态。
6. **只对有真人的会话开放。** 任何自动化/定时/批量路径都不许走到这个工具。
7. **默认关**：一个开关 `SDLC_ASK_USER_QUESTION`（名字你们定），默认关闭。
8. **schema 预算做成配置项**（业主已同意可以加），
   并且**加一条测试断言"当前工具集的 schema 装得下当前预算"** ——
   装不下时测试红，而不是运行时悄悄少一个工具。
   agent 侧另有 `AGENT_MAX_TOOLS_PER_TASK=4`，这个工具在 per-task 裁剪里怎么处理，
   由你们判断（外网的倾向：**它不应该占用 task 的 4 个名额**，
   因为"要不要问人"跟"这个 task 用哪些检索工具"是两件事 —— 但这是你们的判断）。

### B.5 验收

- 一条端到端：模型调用 → turn 以 `pending_question` 结束 → 下一轮带绑定回答 → resume 继续。
- 一条断言：**pending 状态不会被记成 `completed`。**
- 一条断言：**下一轮发一个不带绑定的普通问题 → 走新一轮，不被当成回答。**
- 一条断言：**另一个 owner 看不到这个 pending question。**
- 一条断言：**TTL 到期后的 pending question 是明确的过期态。**
- schema 预算那条断言（B.4-8）。

### B.6 不做什么

- **不做同一连接内阻塞等待。**
- 不做多轮追问链（一次 pause 只问一批）。
- 🔴 **不自动写 `config/`。** 人的回答**是**最值钱的那类知识，
  但把它写进 `config/` 必须是**人 review 之后提交**的动作。
  自动回填会把一个"经过评审的版本库"变成"自动攒出来的东西"，
  而 `config/` 的全部价值就在前者。**把答案原样呈现给人，到此为止。**
- 不新增任何读权限（见 B.4-1）。

## 阶段 C —— 两条纪律，只覆盖 B 新增的面

内网已答"部分接"，外网完全同意这个范围：
**只针对本轮新增的模型可见工具、出口/控制事件和新模块，不回溯改造既有的 45 个 module。**

### C.1「模型眼里长什么样」

给 B 新增的工具和 `pending_question` 事件各写一段，固定三小节：

1. **模型看到的原文** —— 是那段文本本身，不是对它的描述；分场景写
   （schema 长什么样、答案回来长什么样、等人的时候模型看到什么）；
2. **token 影响** —— 固定成本？数据相关？等人的时候花不花 token？
3. **前缀影响** —— 这个面变了会不会打破可复用的请求前缀。

**不做**：不回溯改已有 17 个工具的文档，不新建每模块 README。

### C.2 每模块一条运行时不变量

对本轮新增的模块：要么注册一条**可运行**的检查，
要么写 `No runtime invariant:` ＋ **针对这个模块的**理由（不许是通用套话）。

两条约束：

- 🔴 **verify 必须挂在 pytest 里**（内网 `ci_workflow_files: []`，没有 CI）——
  它得是一个会红的测试，不能是"要人记得跑一下"的脚本。
- **不变量只能断言"事件流或可变数据的关系"**，
  不能断言"某个函数/服务存在" —— 后者是导入的事，写成不变量是凑数。

**不做**：不给既有 45 个 module 补；不引入注册表框架
（本轮就一两个新模块，一个函数 ＋ 一个 pytest 用例足够）。

## 附：这一轮已经钉死、实现时直接用的事实

- `copilot_responses` **严格要求 tool-call / tool-result 成对**：
  把 `tool_result.content` 换成短文本 → OK；**整条删掉 → HTTP 400**
  （`No tool output found for function call`）。
  → **任何上下文操作只许替换内容，不许删除条目。**
- Ask 与 agent **共用 `tools.dispatch` / `tools.dispatch_events`**，
  但**工具结果消费路径不同**（`fit_tool_result` vs `_bounded_payload` ＋ `context_pack.build_fitted`）。
  → 要作用于"工具结果"就挂 dispatch 层；挂预算层只能覆盖一半。
- `incident_investigator._finish()` 是 **先 `redaction.sanitize_packet()`、再 alarm fingerprint、
  最后才 yield** → `dispatch_events()` 交出来的那份已经过闸。
  **本轮不依赖这条**（A、B 都不碰工具结果内容），但将来真要用它，
  **先写一条断言把它钉死，别靠这句话。**
- 这台 Windows 机器上 **POSIX 模式位没有隐私语义**（实测 `0o100666`，
  且存在同机非 owner 可读的 allow ACE）。
  → **任何"写到本地磁盘就算私密"的设计，前提都不成立。**
  本轮 A 的台账因此**只记数字和工具名**（见 A.2-1）—— 这不只是省事，
  是因为那个目录挡不住同机的其他人。
