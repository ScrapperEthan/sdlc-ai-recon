## 一、一句话现状

## 二、Demo 能演到哪 —— 三档,按"还需要什么资料"划分

### 档 1 · 不需要任何新资料,今天就能演

| 演示内容 | 效果 |
| --- | --- |
| 跨仓库影响面分析 | 指定一个仓库或渠道,列出受影响的服务与业务用例,**每条结论都带代码出处** |
| 渠道 → 厂商投递链路图 | 可点击下钻的架构图(短信/邮件/推送/WhatsApp/微信/信函各条通道) |
| 用例配置体检报告 | 2,810 条用例的质量清单:缺渠道配置、优先级为空、分类非法、表达式与优先级互相矛盾等 |
| 自然语言问答 | 直接用中文问,答案带引用可溯源 |

> 这一档是**已经跑通、可复现**的。老板要看的"AI 能替我们看懂这套系统"就在这一档。

### 档 2 · 只差 1 张表,就能补上 Demo 的主角

**完整业务链路图**:源系统(PEGA / MDC / eAlert)→ 业务用例 → 渠道+优先级 → 消息 topic → 投递作业仓库 → 外发 API 仓库 → 厂商 → 客户。

现在这条链**断在"用例 → topic"这一跳**:手上只有 dev/SCT 环境的路由表,UAT 的没有。

补上之后就能回答老板最关心的那个问题:**"某厂商中断,精确到哪几条业务受影响"** —— 这是事故响应和变更通知的核心价值。

### 档 3 · 需要业务方回答 3 个问题,才能从"标出矛盾"升级为"判定对错"

现在工具能说"这两处配置**不一致**",但不能说"**哪个是对的**"。
因为渠道规则表达式里的 `>` `&` `|` 到底什么意思,代码里没有权威定义,而且现行程序本身的解析逻辑就有 bug——所以我们**故意不猜**,只标记矛盾。业务方给了定义,同一批数据就能直接给出判定结论。

## 三、下一步要做的两件事

### 事项 1 · 数据自维护改造(**不需要任何资料,可立即开始**)

**做什么**:把"业务表长什么样"(列名、渠道清单、厂商名单等)从程序内部搬到外挂配置文件。

**为什么**:今天表一变(改列名、加渠道、新厂商),必须改程序内部代码,而这只能由外部开发做,内外网又不通,只能靠人工截图转述,一次往返数天。
**证据**:过去三次线上问题修复(RUNBOOK-49/50/51),查代码记录,改的全是同一个文件,内容都只是**往厂商名单里加一个名字**。三次都不该占用开发资源。

**效果**:
- 表结构变化由**内网 codex 独立完成**,改配置文件即可,不动程序、不排队等开发、不需要人工转述
- 内网侧的真实配置存进内网 github,**不会丢**,且**真实数据永不出内网**(合规更干净)
- 分工固化:**内网维护数据 / 外部维护引擎**

**风险**:极低。这是纯搬家,验收标准是**搬完前后产出的结果文件逐字节一致**。

### 事项 2 · 补齐完整链路图(**需要档 2 那张表**)

拿到 UAT 路由表后,把断掉的那一跳接上,链路图端到端打通。

## 五、需要业务方回答的 3 个问题(**这三件事代码里查不到,只能问人**)

| 问题 | 问谁 | 拿到后的效果 |
| --- | --- | --- |
| **业务分类 33 和 37 的正式名称是什么?** ⚠️**建议优先** | 业务负责人 | 这两个分类在程序里没有登记,而运行时会**拒绝无法识别的分类** → 目前有 **7 条已启用用例**可能正处于配置非法状态。这是一个现实隐患,不只是数据问题 |
| **渠道规则表达式里 `>` `&` `\|` 各是什么含义?**(例:`LETTER > (EMAIL & SMS)`) | MDC 系统开发/产品负责人 | 让工具从"标出矛盾"升级为"判定对错"(档 3)。已发现该表达式与优先级配置、与前台页面显示**三方互相矛盾**的实例 |
| **`source_system` 有没有权威登记表(CMDB)?** | 企业架构 | 目前该字段是自由文本,已出现 154 种写法变体(eAlert/e-Alert、PowerCard/Power Card 等),靠规则归并。有权威清单就能校验 |

> 答案是**一次性**的:拿到后写进配置文件即刻生效,**不需要改代码**,以后也不用再问。

## 六、诚实的边界(汇报时请一并说明,避免误解)

- 上述所有数据结论来自 **UAT 环境快照**,**不等于生产环境已验证**。
- "约 251 条配置风险"是**需要人工复核的清单**,不是"已确认的故障"。其中 7 条(分类 33/37)证据较强。
- 我们已发现的运行时代码风险(状态过滤缺失、空值保护缺失等)**不属于本项目修改范围**,已整理成待提交给 MDC 系统负责人的问题单。
- 这些运行时风险的确认还缺一份**UAT 部署清单**(镜像/版本/提交号)——没有它,只能说"潜在",不能说"确认"。
